## What actually Spring doing in respect of creating Object of a class
Spring actually creates an object of a class using a technique called Dependency Injection (DI). In Spring, instead of the application code creating objects directly using the `new` keyword, Spring manages the lifecycle and dependencies of objects for you.

Here's how it works:
1. **Bean Definition**: In Spring, classes that you want to manage as objects (beans) are defined in the Spring configuration. This can be done using XML configuration, Java-based configuration (using `@Configuration` and `@Bean` annotations), or component scanning (using annotations like `@Component`, `@Service`, `@Repository`, etc.).
2. **Dependency Injection**: When Spring creates an object (bean), it automatically injects the required dependencies into that object. This can be done through constructor injection, setter injection, or field injection. Spring resolves the dependencies based on the configuration and the context of the application.
3. **Inversion of Control (IoC)**: Spring follows the IoC principle, which means that the control of object creation and dependency management is inverted from the application code to the Spring container. The Spring container is responsible for creating and managing the lifecycle of beans, allowing developers to focus on business logic rather than object creation and dependency management.
4. **Lifecycle Management**: Spring manages the entire lifecycle of beans, including their creation, initialization, and destruction. It also provides hooks for custom initialization and destruction methods, allowing developers to perform specific actions during the lifecycle of a bean.

In summary, Spring creates objects of classes by managing their lifecycle and dependencies through Dependency Injection and Inversion of Control.

#### When Spring creates an object of a class, it does so by following these steps:
1. **Class Scanning**: Spring scans the classpath for classes annotated with specific annotations (e.g., `@Component`, `@Service`, `@Repository`, etc.) or defined in the configuration. These classes are candidates for being managed as beans by the Spring container.
2. **Bean Definition**: For each candidate class, Spring creates a bean definition that contains metadata about the class, such as its name, scope, and dependencies. This bean definition is stored in the Spring container.
3. **Dependency Resolution**: Spring resolves the dependencies of the bean by checking the constructor parameters, setter methods, or fields annotated with `@Autowired`. It looks for other beans in the container that match the required types and injects them into the bean.
4. **Bean Instantiation**: Spring creates an instance of the bean by calling its constructor. If the bean has dependencies, Spring injects them during this step.
5. **Initialization**: After the bean is instantiated, Spring performs any necessary initialization, such as calling methods annotated with `@PostConstruct` or executing custom initialization logic defined in the bean's configuration.
6. **Bean Usage**: Once the bean is fully initialized, it is ready to be used by the application. The Spring container manages the lifecycle of the bean, including its destruction when it is no longer needed.
7. **Bean Destruction**: When the Spring container is shut down or the bean is no longer needed, it performs any necessary cleanup operations, such as calling methods annotated with `@PreDestroy` or executing custom destruction logic defined in the bean's configuration.
8. **Scope Management**: Spring supports different bean scopes (e.g., singleton, prototype, request, session) that determine how many instances of a bean are created and how they are shared within the application. The scope is defined in the bean definition and affects the lifecycle of the bean.
9. **Proxy Creation (Optional)**: In some cases, Spring may create a proxy for the bean to provide additional functionality, such as transaction management, security, or lazy loading. The proxy intercepts method calls to the bean and adds the desired behavior before delegating to the actual bean instance.
10. **Context Awareness**: Spring beans can be aware of the application context and other beans in the container. This allows them to interact with other components and access shared resources, such as configuration properties, message sources, or event publishers.
11. **Event Handling**: Spring provides an event-driven programming model that allows beans to publish and listen for events. Beans can register as event listeners and respond to specific events, enabling decoupled communication between components in the application.
12. **Aspect-Oriented Programming (AOP)**: Spring supports AOP, which allows developers to define cross-cutting concerns (e.g., logging, security, transactions) separately from the business logic. Spring can create proxies for beans to apply aspects, enabling modularization of concerns and improving code maintainability.
13. **Configuration Management**: Spring provides a flexible configuration management system that allows developers to externalize configuration properties and manage them in a centralized manner. Beans can access configuration properties through annotations, property files, or environment variables, enabling easy customization and deployment of applications.
14. **Testing Support**: Spring provides comprehensive testing support for beans and the application context. Developers can write unit tests, integration tests, and end-to-end tests using Spring's testing framework, which allows for easy mocking of dependencies and verification of bean behavior in isolation or within the context of the application.
15. **Lifecycle Callbacks**: Spring allows beans to define lifecycle callbacks, such as `@PostConstruct` and `@PreDestroy`, which are invoked at specific points in the bean's lifecycle. This enables developers to perform custom initialization and cleanup tasks, ensuring that resources are properly managed and released when the bean is no longer needed.
16. **Bean Post-Processors**: Spring provides a mechanism for customizing the behavior of beans through bean post-processors. These are special beans that can intercept the creation and initialization of other beans, allowing developers to modify their properties, apply additional logic, or perform validation before the bean is fully initialized.
17. **Conditional Bean Creation**: Spring allows for conditional bean creation based on specific criteria, such as the presence of certain classes, properties, or environment variables. This enables developers to create beans only when certain conditions are met, allowing for more flexible and dynamic application configurations.
18. **Profiles and Environment Management**: Spring supports the concept of profiles, which allows developers to define different configurations for different environments (e.g., development, testing, production). Beans can be created or excluded based on the active profile, enabling easy management of environment-specific settings and behavior.
19. **Integration with Other Frameworks**: Spring can be easily integrated with other frameworks and libraries, such as Hibernate, JPA, JMS, and more. This allows developers to leverage the capabilities of these frameworks while benefiting from Spring's features, such as dependency injection, transaction management, and AOP, resulting in a more cohesive and maintainable application architecture.
20. **Documentation and Community Support**: Spring has extensive documentation and a large, active community that provides support, tutorials, and best practices for using the framework. Developers can access official documentation, community forums, and online resources to learn about Spring's features, troubleshoot issues, and share knowledge with other developers, ensuring that they can effectively utilize the framework and build robust applications.
21. **Continuous Improvement and Updates**: Spring is continuously evolving, with regular updates and new features being added to the framework. The Spring team actively maintains the framework, addressing bugs, security vulnerabilities, and performance improvements. Developers can stay up-to-date with the latest releases and take advantage of new features to enhance their applications and improve development efficiency.
22. **Best Practices and Design Patterns**: Spring encourages the use of best practices and design patterns, such as the Singleton pattern, Factory pattern, and Dependency Injection pattern. By following these practices, developers can create modular, maintainable, and testable code that adheres to industry standards and promotes code reusability.
