### Spring Security

#### CSRF(Cross-Site Request Forgery) Protection
- CSRF is a type of attack that tricks the victim into submitting a malicious request. It can be prevented by using CSRF tokens, which are unique and secret values generated by the server and included in each request. The server validates the token to ensure that the request is legitimate.
- In Spring Security, CSRF protection is enabled by default for all HTTP methods that can change state (e.g., POST, PUT, DELETE). It can be disabled for specific endpoints or HTTP methods if necessary, but it is generally recommended to keep it enabled for security reasons.
- To disable CSRF protection for specific endpoints, you can configure the `HttpSecurity` object in your security configuration class. For example:
```java
@Override
private void configure(HttpSecurity http) throws Exception {
    http
        .csrf().disable() // Disable CSRF protection for all endpoints
        .authorizeRequests()
            .antMatchers("/public/**").permitAll() // Allow public endpoints without authentication
            .anyRequest().authenticated(); // Require authentication for all other endpoints
}
```

##### How to validate a CSRF token in a Spring Security application:
1. When a user logs in or accesses a protected resource, the server generates a CSRF token and includes it in the response. This token is typically stored in a cookie or as a hidden field in the HTML form.
2. When the user submits a request that modifies state (e.g., POST, PUT, DELETE), the CSRF token must be included in the request. This can be done by including the token in the request headers or as a form parameter.
3. The server validates the CSRF token by comparing it with the token stored on the server. If the tokens match, the request is considered valid and processed. If the tokens do not match or are missing, the server rejects the request and returns an error response (e.g., HTTP 403 Forbidden).
4. In Spring Security, the CSRF token validation is handled automatically by the framework. When CSRF protection is enabled, Spring Security checks for the presence of a valid CSRF token in the request and performs the validation. If the token is missing or invalid, Spring Security will reject the request and return an error response.
5. To customize the CSRF token validation behavior, you can implement a custom `CsrfTokenRepository` or use the default implementation provided by Spring Security. The default implementation stores the CSRF token in the HTTP session and generates a new token for each session. You can also configure the token repository to use cookies or other storage mechanisms if needed.
6. In summary, CSRF protection in Spring Security is an important security feature that helps prevent malicious requests from being executed on behalf of authenticated users. By validating CSRF tokens, the server ensures that requests are legitimate and protects against CSRF attacks.

##### In POST Request of POSTMAN we can validate the CSRF token by including it in the request headers or as a form parameter. For example, if the CSRF token is stored in a cookie named `XSRF-TOKEN`, you can include it in the request headers as follows:
```
X-XSRF-TOKEN: <value of the CSRF token>
```
